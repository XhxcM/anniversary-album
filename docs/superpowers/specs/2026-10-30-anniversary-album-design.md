# 一周年动态网页相册设计规格

- 状态：设计已确认
- 日期：2026-10-30
- 正式展示日：2026-12-14
- 在一起的起始日期：2025-12-14

## 1. 目标

制作一个通过非公开链接访问的一周年纪念网页相册。网站展示 40–60 张情侣生活照片，以“黄昏电影”为视觉方向，通过 Three.js 将照片依次排列为记忆长河、无限轨迹和双心共振。电脑端支持悬停浮起与点击放大；手机端要求横屏，点击照片后可左右滑动查看。

网站必须同时适用于电脑浏览器、手机 Safari/Chrome 和微信内置浏览器。核心内容在 WebGL 不可用、设备性能不足或用户开启“减少动态效果”时仍可访问。

## 2. 明确不做

- 不做账号、密码、数据库或后台管理。
- 不做在线上传器或网页内永久编辑。
- 不做公开图库、评论、分享按钮或社交功能。
- 不做 3D 相机旋转、粒子爆炸、复杂后期处理或自动快速轮播。
- 不把简单的标题、按钮、说明和放大查看层绘制到 WebGL 中。
- 不把“网页密码页”伪装成真正的访问保护。

## 3. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 礼物用途 | 一周年纪念日礼物 |
| 照片数量 | 精选 40–60 张 |
| 视觉方向 | 黄昏电影：酒红暗场、琥珀高光、暖色胶片边框 |
| 开场 | 一张重要合照铺满屏幕 |
| 实时天数 | 从 2025-12-14 起计算经过的完整天数 |
| 章节推进 | 每章全屏；一次滚动或横向滑动前进一章 |
| 章节内运动 | 自动进行轻微漂浮和景深变化 |
| 阵型 | 记忆长河、无限轨迹、双心共振 |
| 电脑交互 | 悬停浮起；点击放大；方向键切换；Esc 关闭 |
| 手机交互 | 竖屏提示旋转；横屏单击放大；左右滑动切换照片 |
| 照片说明 | 可选；只在放大查看时显示 |
| 音乐 | 预留 `music.mp3`；开场按钮首次点击后播放 |
| 告白文字 | 预留空内容，用户之后自行填写 |
| 内容维护 | 编辑一个内容配置文件并替换素材文件 |
| 发布保护 | 仅凭不公开链接访问；无身份验证 |
| 技术选择 | Vue 3、Vite、Three.js |

## 4. 完整观看流程

1. 手机竖屏时显示旋转提示；电脑或横屏手机直接进入开场。
2. 开场使用主照片全屏铺底，显示 `Our First Anniversary`、实时天数与“开启我们的回忆”按钮。
3. 点击按钮后开始播放音乐并进入照片舞台。音乐启动依赖该用户手势，不尝试绕过浏览器限制。
4. 每次滚动、触控横向滑动或键盘导航只切换一个章节。
5. 章节切换使用同一 Three.js 舞台完成照片位置插值，不重建整个页面。
6. 点击照片时暂停照片舞台，打开 DOM 放大层；关闭后恢复舞台。
7. 最后一章结束后回到开场主照片，音乐降低音量，展示告白文字和“重新观看”。

## 5. 章节与动画

### 5.1 故事开始的地方

- 展示相识和刚在一起时的照片。
- 照片从暗处逐张靠近，形成稀疏的记忆长河。
- 这是运动最慢的章节，让早期照片有充足停留时间。

### 5.2 平凡日子也闪闪发光

- 展示吃饭、散步、居家和搞怪等日常照片。
- 延续记忆长河，增加照片密度、前后景层次和轻微视差。
- 不增加第四种阵型。

### 5.3 一起走过的地方

- 展示约会和旅行照片。
- 记忆长河交叉汇合为无限轨迹。
- 照片运动幅度在此章最大，但相机保持稳定，不旋转视野。

### 5.4 特别瞬间与纪念日

- 展示生日、节日和重要合照。
- 照片运动逐渐放慢，所有章节的小尺寸纹理汇聚为两颗心。
- 舞台中央显示实时天数，形成全站视觉高潮。
- 若设备无法稳定承载全部纹理，使用按顺序均匀抽取的照片子集，不重复照片。

### 5.5 未完待续

- 3D 照片退入暗处，开场主照片重新出现。
- 音乐缓慢降低音量，但不自动停止。
- 展示用户后续填写的告白文字和“重新观看”按钮。

## 6. 动画和输入规则

- 章节转场目标时长为 0.8–1.2 秒。
- 转场期间忽略重复滚轮、滑动和键盘输入，避免连续跳章。
- 电脑悬停照片时，命中照片向镜头移动并轻微放大；离开后回到当前阵型位置。
- Three.js 使用射线检测处理鼠标命中，DOM 放大层处理查看与导航。
- 手机没有悬停步骤；单击直接放大。
- 放大层支持桌面左右按钮、方向键、Esc，支持手机左右滑动与点击关闭。
- 放大层打开时暂停 Three.js 运动，音乐继续播放。
- 页面进入后台时暂停渲染循环；恢复可见时继续。
- 音乐控件提供静音与恢复，不依赖自动全屏。
- 系统启用 `prefers-reduced-motion: reduce` 时取消大幅空间移动，使用静态阵型与短淡化。

## 7. 技术架构

### 7.1 Vue 界面层

Vue 负责：

- 开场页与实时天数。
- 横屏提示、章节进度和输入锁定状态。
- 音乐控制。
- 放大查看层与可选照片说明。
- 结尾告白与重新观看。

项目不引入 Vue Router、Pinia 或组件库。

### 7.2 Three.js 照片舞台

Three.js 负责：

- 照片平面、景深和阵型坐标。
- 章节间位置、旋转、透明度和缩放插值。
- 鼠标射线检测与悬停状态。
- WebGL 能力与渲染性能检测。

渲染器像素比上限为 `1.5`，避免高分辨率手机过度消耗 GPU。当前章节与下一章节可同时驻留以完成转场；离开转场后释放不再需要的几何体和纹理。最后的双心场景只使用小尺寸纹理。

### 7.3 内容层

`public/content.js` 在应用启动前加载，并定义 `window.ALBUM_CONTENT`。它只保存公开展示内容，不保存密码、密钥或令牌。

推荐结构：

```js
window.ALBUM_CONTENT = {
  startDate: "2025-12-14",
  timeZone: "Asia/Shanghai",
  cover: "./media/cover.jpg",
  music: "./media/music.mp3",
  letter: "",
  chapters: [
    {
      id: "beginning",
      title: "故事开始的地方",
      folder: "01-故事开始",
      photos: [
        { file: "01", caption: "" }
      ]
    }
  ]
};
```

运行时根据章节 `folder` 和照片 `file` 推导小图与大图路径，用户不需要为一张照片重复填写两个地址。

## 8. 实时天数

- 以 `Asia/Shanghai` 的自然日为准，不依赖访问者设备所在时区。
- 计算从 2025-12-14 到当前上海日期之间经过的完整天数。
- 2026-12-14 必须显示 `365`。
- 页面跨过上海午夜仍保持打开时，自动重新计算并更新天数。
- 日期配置无效时不显示错误数字，改为显示中性纪念日标题并记录可诊断错误。

## 9. 素材与照片处理

用户提供的原照片按以下目录整理：

```text
originals/
  01-故事开始/
  02-平凡日常/
  03-一起走过/
  04-纪念日/
```

`scripts/prepare-photos.mjs` 读取原照片并生成网页副本：

- 小图：供 Three.js 使用，限制尺寸并压缩为 WebP。
- 大图：供放大查看使用，限制最长边并压缩为 WebP。
- 自动校正方向。
- 去除 EXIF 和定位信息。
- 永不覆盖 `originals/` 中的原文件。
- 遇到无法可靠处理的 HEIC 时明确失败并列出文件，要求先导出为 JPG；不静默丢图。

处理脚本使用开发依赖 `sharp`，通过 `npm run prepare-media` 执行。`originals/` 与 `public/media/` 必须加入 `.gitignore`，避免把原照片或生成照片意外提交到远程代码仓库。

应用只预加载开场和第一章；后续章节的小图在空闲时间加载。放大查看的大图只在用户打开照片时加载，并预取相邻一张。

## 10. 容错与降级

- `music.mp3` 缺失或无法播放：隐藏音乐控制，其他功能继续工作。
- 单张图片损坏：显示电影胶片式占位框，不阻断章节。
- `content.js` 字段缺失：使用安全默认值；严重结构错误时显示可读提示，不呈现空白页。
- WebGL 不可用或上下文丢失：切换为普通 DOM 照片墙，保留章节、照片说明和放大查看。
- 首章稳定后连续 3 秒平均帧率低于 24 FPS：先把像素比降至 `1` 并减少同时显示的照片；再次连续 3 秒低于 24 FPS 时切换为普通照片墙。
- 微信不允许全屏：维持普通横屏网页，不把全屏作为核心依赖。
- 设备始终保持竖屏：允许用户从提示页继续进入兼容布局，不形成死循环。

## 11. 可访问性与隐私

- 所有按钮使用真实 HTML 按钮并有可见名称。
- 放大层打开后管理焦点，关闭时把焦点还给原照片。
- 重要操作不依赖颜色或悬停。
- 照片说明以纯文本渲染，不执行 HTML。
- `robots.txt` 与页面元数据使用 `noindex, nofollow`，降低被搜索引擎收录的可能。
- 网站不包含姓名，只展示一周年、实时天数和用户自行填写的内容。
- “仅凭链接访问”不是加密或身份验证；链接被转发后其他人也能查看。

## 13. 发布方式

使用 Vite 生成 `dist/`，再通过 Netlify 手动部署该构建目录。首次发布后保留同一项目；内容更新时重新执行照片处理和构建，再上传新的 `dist/`。

网址使用无实际含义的名称，并明确告知用户：未公开网址和 `noindex` 只降低被发现的概率，不提供访问控制。

## 14. 验证与完成标准

### 14.1 自动检查

- 天数测试覆盖 2025-12-14、2026-12-14 和跨年边界。
- 阵型测试确保所有坐标有限、照片数量变化时不越界、不重复索引。
- 内容测试覆盖空告白、空说明、缺失音乐、损坏照片条目和无效日期。
- `npm test` 通过。
- `npm run build` 通过。

### 14.2 浏览器验收

- 2026-12-14 显示 `365 天`，之后每天正确增加。
- 页面不出现双方姓名。
- 电脑端悬停、点击、方向键和 Esc 均有效。
- 手机竖屏显示旋转提示，横屏后保留当前章节。
- 手机上单击照片放大，左右滑动切换。
- 一次输入只切换一个章节。
- 阵型按记忆长河、无限轨迹、双心共振出现。
- 音乐只在开场按钮点击后启动；音乐缺失时网站仍可用。
- WebGL 降级与“减少动态效果”模式保留完整内容。
- 损坏图片不导致页面崩溃。
- 网页照片副本不包含定位元数据。
- 使用真实照片后检查首屏加载、显存占用和触控流畅度。
- 至少在桌面 Chrome/Edge、手机 Safari/Chrome 和微信内置浏览器中实际打开一次。

## 15. 已知限制

- 未提供真实照片前，无法确认最终裁切、纹理数量和低端手机显存表现。
- 微信与手机浏览器的音乐、横屏和 WebGL 表现不能只靠桌面模拟器证明，发布前必须使用真实手机验证。
- 背景音乐的版权由用户自行确认；私密链接不代表获得传播授权。
- 告白文字、音乐文件、主照片和章节照片将在实现后由用户补充。
